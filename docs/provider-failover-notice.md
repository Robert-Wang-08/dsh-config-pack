# failover 可见性、按类别重试与同族互备（2026-10-15）

本文记录 `dsh-deepseek-keypool` 在 v3.4.0 之上的三项本地改动，以及它们的验证与回滚方式。
背景事实与证据见工作区 `.ptc-probe/failover-switch-incident.json`。

## 1. 会话内可见的通知（原因 + 结果）

**问题**：失败切换只写 `console.warn` 与内存环形缓冲（上限 50 条、条目无 sessionId），
会话里看不到任何提示；模型选择器只会**下一次请求后**通过 `request/header` 间接反映新路由，
用户无法知道「为什么换了、换到了哪」。

**做法**：插件新增按会话归档的通知。

- 表项：`noticeId`（稳定、可去重补拉）、`at`、`session`、`kind`（`failover` / `retry` / `startup-align`）、
  `stage`（`selected` / `retrying`，**绝不把选中候选写成“已成功”**）、`code`、`trigger`、
  `fromRoute`/`fromModel`、`toRoute`/`toModel`、`tier`、`reasoningEffort`、`turn`/`step`。
- 存储：内存每会话上限 200 条 + 追加落盘 `$DSH_HOME/plugins/provider-failover/notices.jsonl`，
  因此环形缓冲轮转后仍可回看；落盘失败只告警，不影响切换。
- 取数：`GET /provider-failover/notices?sessionId=<id>&limit=<n>&after=<noticeId>`（同源限定）。
- 展示：插件 `client.js` 注册 `conversation.input.dock`（session 作用域），在**会话输入区上方**
  显示最新一条，可展开历史；浏览器刷新后照常显示。
- 边界：通知**不进入 Session surface、不进入模型上下文**；会话导出/分叉不会自动携带插件侧通知历史。

## 2. 按失败类别的重试策略

以前所有可切换失败都是「立即切换 provider」。现在按类别区分（`retryPolicies`，可在 profile patch 覆盖）：

| 类别 | 策略 | 理由 |
|---|---|---|
| `TRANSPORT` | 等 **5s** 原地重试，最多 **5** 次或 **30s** 预算；连接活过 `observationWindowMs`(30s) 才断则视为意外中断，按预算重试；预算内没成功才切换 | WebSocket/SSE 掉线多为瞬时抖动，直接换模型代价过大 |
| `RATE_LIMIT` | 退避 15s 重试，最多 3 次或 60s 预算 | 限流会自愈，换 provider 往往只是把限流带过去 |
| `SERVER` | 3s 重试最多 2 次或 15s 预算 | 上游 5xx |
| `QUOTA` | **立即切换**（attempts 0） | 额度耗尽重试无意义 |
| `AUTH` / `INVALID_CREDENTIAL` / `MISSING_CREDENTIAL` | **立即切换**（有 `keys` 时先换 key，同路由同模型） | 凭据问题换 key 才有效 |
| `NO_ADAPTER` | **立即切换** | 路由未注册 |
| 未列出的错误码 | **立即切换**（不重试） | 新错误码绝不因“默认值”被静默改成先重试 |

同时补齐消息模式兜底：新增 `websocket error`、`websocket` 两个 pattern 与其 `TRANSPORT` 归类。
此前 pi-ai 的原生文案就是裸的 `WebSocket error`（宿主编码 `PI_AI_ERROR`），
既不在 `terminalCodes` 也不在 pattern 表里，**既不会重试也不会切换**，直接交回宿主。

另外：确认可切换失败但**档位表里没有可用候选**时，现在会写一条 `category: 'no-candidate'` 的
ignored 记录，避免证据里分不清「没触发」与「触发了但没得切」。

## 3. 同族互备优先于档位优先级

`ranking.sameTierFirst`（布尔，默认 `false` = 保持旧语义）：
打开后失败路由能在档位表中定位时，**先只扫它所在的那一档**，档内确实无可用候选
（已尝试 / 冷却中 / 能力不兼容 / 不可解析）才退回「从第 1 档向上扫」。

效果：`opencode-go` 失败先切同档的 `ais-2dsglm`（同为 `deepseek-v4.1-flash`），
而不是直接升到第 1 档的 `gpt-5.6-sol`；整档耗尽才升档。本机已在
`config/45-failover.yml` 设为 `true`，并同步写入 45 里的 `retryPolicies`。
插件默认值仍是 `false`，因此未显式配置的安装行为不变。

## 限制与回滚

- 通知面板位置是**输入区上方**，不是原生聊天时间线。要出原生持久卡需要宿主先补
  `dsh-session` 的 informational/`ignorable` append API（见
  `dsh-session/lib/index.js` 的 `append` 只复制 `surfaceOp`/`sourceEventSeqs`），属独立任务。
- 插件加载改动需要**重启 DSH profile**（插件在宿主进程内加载）。重启后刷新
  `http://127.0.0.1:3080`；浏览器可能缓存 `client.js`，必要时强制刷新。
- 回滚：`git -C dsh-provider-failover checkout -- index.js client.js` 并重新同步到
  `$DSH_HOME/profiles/web/node_modules/dsh-deepseek-keypool/`；配置侧把
  `45-failover.yml` 的 `sameTierFirst` 改回 `false`、删除 `retryPolicies` 即回到旧语义。

## 4. 手动切换（模型选择器 / 测试切换）也在会话内可见

**宿主本来就会做的事**：`dsh-agent/lib/types/model-selection.js:12-26` 定义的
`modelSwitchNotice` 会在 provider/model 变化时，向**下一次被接纳的请求**追加一条持久的
user-role 提示：`[model changed: assistant turns above this point were generated by A; the session continues with B]`
（仅 provider/model 变化才追加，纯 effort 变化不追加）。所以手动切换在聊天时间线里本来就有痕迹，
但**没有切换原因**，也看不出是"谁切的"。

**本插件补充的部分**：`agent/request` 在 `next()` 之后观测**实际下发的 provider/model**
（此时所有 hook 已处理完，因此模型选择器 / `/failover-test` / 宿主其它入口造成的变更都会现形），
与上一次下发值不同即记一条通知：

- `kind: 'manual-switch'`，`code: 'MANUAL'`，`trigger: 'observed:route-change'`，带 turn/step 与生效 effort；
- `/failover-test` 与设置页「测试切换」走 `applyTestSwitch`，记 `code: 'TEST'`、`trigger` 为切换来源；
- 插件自己发起的切换（failover / 启动对齐 / 测试切换）在切换当刻就把观测值更新为目标路由，
  因此**不会被重复记成"手动切换"**。

## 5. 生效时机（实测源码口径）

| 切换方式 | 生效时机 | 依据 |
|---|---|---|
| 手动选模型（选择器 / `/failover-test` / API) | **下一步**生效：`system-prompt/assemble` 快照选择，`agent/request` 应用该 provider/model/effort；正在飞行的请求保持原路由。**不是等下一轮** | `dsh-agent/lib/types/model-selection.js:45-75`（`selection.current` → `selection.assembled` → 覆盖 `agent/request` 结果）、`dsh-api-session-controller/lib/types/agent.js:349-352` |
| 自动故障转移（本插件） | **立即生效（同一步）**：`agent/request-error` 在 `{ kind: 'retry' }` 之前就改写了 provider/model，同一步重试即用新路由；因为**不经过** selection 通路，也不消耗一次"下一步" | `index.js` 的 `agent/request-error` 切换分支与 `agent/request` 的 target 分支 |
| 按类别原地重试（TRANSPORT/RATE_LIMIT/SERVER） | 等待 `delayMs` 后**同一步**重试同一路由；预算用尽才切换 provider | `index.js` 的 `transientRetryGate` |
